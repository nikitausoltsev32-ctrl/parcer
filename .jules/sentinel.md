## 2024-03-24 - Fix Open Redirect in Tracking Endpoint
**Vulnerability:** Open Redirect in `track_click` endpoint (`/t/click/{tracking_id}`). When a request with an invalid signature was received, the application redirected the user to the provided destination URL (`url` query parameter) with a 302 status code instead of failing or returning an error.
**Learning:** Redirect endpoints must actively return an HTTP error response (like a 400 Bad Request) on signature verification failures instead of falling through to a redirect, which effectively bypasses the signature check and allows arbitrary redirection (Open Redirect). Furthermore, manually calling `urllib.parse.unquote` on query parameters like `url` introduces double-unquoting issues, as FastAPI automatically unquotes query string parameters during request binding.
**Prevention:** Always fail securely on authentication/authorization failures in redirect endpoints by explicitly returning error responses. Rely on the framework's native unquoting to prevent double-unquoting or encoding bypass vulnerabilities.
