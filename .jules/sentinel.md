## 2024-05-17 - Open Redirect & Double Unquoting in Tracking Endpoint
**Vulnerability:** Open redirect vulnerability combined with a double-unquoting flaw in the click tracking endpoint. A manually called `urllib.parse.unquote` on `url` (which FastAPI already unquotes) combined with redirecting upon signature verification failure (`if not verify(...): return RedirectResponse(url=destination)`) allowed arbitrary redirects if an invalid signature was provided.
**Learning:** Returning a `RedirectResponse` on signature verification failures fails open, allowing Open Redirect attacks. Additionally, FastAPI automatically unquotes query parameters, so manual unquoting causes double-unquoting bugs, leading to signature verification failures if URLs contain valid encoded sequences.
**Prevention:** Always return a hard HTTP error (e.g., 400 Bad Request) on signature/auth failure for tracking endpoints instead of redirecting. Rely on FastAPI's automatic query parameter unquoting rather than manual `unquote` calls.
