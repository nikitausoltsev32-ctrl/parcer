## 2024-05-12 - Fix Open Redirect in Tracking URLs
**Vulnerability:** Open Redirect vulnerability in `track_click` endpoint (`/api/v1/t/click/{tracking_id}`).
**Learning:** The URL validation relied on cryptographic verification of the tracking ID alone (`sign(tracking_id)`), ignoring the destination `url` parameter. If the signature for `tracking_id` was invalid, the API failed open by instantly redirecting to the unverified user-supplied URL parameter `url` instead of returning a 4xx error. This allowed attackers to use valid base tracking URLs with arbitrarily modified malicious `url` parameters or random `tracking_id` + invalid `sig` to achieve a successful redirect to a phishing page.
**Prevention:** 1. Cryptographically bind all critical metadata (like the target destination URL) to the signature payload (`sign(tracking_id, destination)`). 2. Fail securely—if cryptographic signature validation fails, immediately halt and return a 4xx HTTP error (`HTMLResponse` with `400 Bad Request`), never proceed to execute the sensitive action (redirection).
