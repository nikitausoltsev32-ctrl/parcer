# ADR 0002 — LLM: Qwen + GLM + Groq

> Status: accepted
> Date: 2026-04-24

## Контекст
Изначально планировались YandexGPT и GigaChat как РФ-провайдеры под 152-ФЗ. Проблема: слабый tool-calling, нужный для чат-агента. Для качественного chat-first UX нужна модель с надёжным function-calling.

## Решение
Три провайдера, все через OpenAI-совместимый HTTP API (единый адаптер):

| Задача | Провайдер | Модель |
|---|---|---|
| Chat-агент (tool-calling) | **Groq** | `llama-3.3-70b-versatile` |
| Генерация писем на русском | **Qwen** (DashScope) | `qwen2.5-72b-instruct` |
| Классификация inbox | **Groq** | `llama-3.1-8b-instant` |
| Fallback (всё) | **GLM** (Zhipu) | `glm-4` |

## Последствия
- ➕ Groq даёт ~500 tok/s → мгновенный чат.
- ➕ Qwen — лучший русский из трёх.
- ➕ OpenAI-совместимость → один SDK `openai` с разными `base_url`.
- ➖ Все три — **не РФ**. Данные клиентов пользователя уходят в Китай (Qwen, GLM) и США (Groq). Трансграничная передача.
- ➖ Требуется отдельное согласие пользователя (чекбокс при онбординге) + упоминание в оферте и политике.
- ➖ Репутационный риск для малого бизнеса, обрабатывающего данные физлиц (хотя в B2B outreach это в основном юрлица).

## Защита пользователя
- `users.llm_consent_at` — timestamp согласия. Без него AI-функции заблокированы.
- В UI — видимая плашка на чате: «AI-функции используют зарубежные модели».
- В будущем — «offline-режим» без AI для особо чувствительных случаев (вне MVP).

## Альтернативы отклонены
- **YandexGPT Pro + GigaChat Pro:** качество tool-calling ниже; GigaChat tool-use появился недавно. Для чат-агента недостаточно надёжен.
- **OpenAI/Anthropic:** дороже, трансграничка та же (США).
- **Self-hosted Llama:** нужен GPU, нецелесообразно для MVP.
