# ADR 0003 — Chat-first UI вместо wizard

> Status: accepted
> Date: 2026-04-24

## Контекст
Изначально главным путём был 4-шаговый wizard («Кого ищем → Проверь список → Что пишем → Отправляем»). Гипотеза: wizard даёт линейность и снижает выбор.

Проблема: целевая персона (ИП/фрилансер/микро-агентство без опыта outreach) воспринимает форму из 4 шагов как «работу». ChatGPT-подобный интерфейс стал стандартом для AI-продуктов 2024–2026 и знаком пользователю.

## Решение
- **Главный экран — чат** (в стиле ChatGPT). Инпут снизу + 3–4 быстрых действия.
- Сообщения ассистента могут содержать **интерактивные карточки**: таблицы лидов, превью писем, прогресс-бары кампаний, кнопки действий.
- Chat-агент работает через **tool-calling** — набор функций, которые он вызывает (import_csv, create_campaign, send_campaign, check_inbox, add_note, set_reminder и т.д.).
- **Классические экраны** (CRM, Campaigns, Inbox, Templates, SMTP) остаются в левом меню как альтернативный путь для опытных пользователей.
- Wizard как отдельного flow не существует.

## Последствия
- ➕ Низкий порог входа: пользователь просто пишет «нужны клиенты» — дальше ведёт AI.
- ➕ Conversational onboarding заменяет форму бизнес-профиля.
- ➕ AI проактивно уведомляет («Алексей ответил заинтересованно») — превращает продукт из инструмента в ассистента.
- ➖ Сложность реализации: SSE-стрим tool-calling, карточки-в-чате как first-class UI-примитив.
- ➖ Для async-операций (генерация 50 писем) ассистент должен возвращаться позже — нужна отдельная система уведомлений внутри чата.
- ➖ Качество tool-use зависит от модели (выбран Groq Llama 3.3 — см. ADR-0002).
- ➖ Пользователи, не знающие, что спросить — для них есть quick-action кнопки и классический интерфейс.

## Альтернативы отклонены
- **Wizard + ассистент-помощник сбоку:** два UI-паттерна конкурируют за внимание.
- **Только классические экраны:** не использует AI-native метафору, конкуренты (особенно западные) уже сдвинулись в чат.
