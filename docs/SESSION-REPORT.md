## 1. Плавные анимации фронта ✅

**Что тормозило:** в `frontend/src/index.css` два `position:fixed` полноэкранных свечения (`body::before` 520px, `body::after` 420px, каждый — radial-gradient) + градиент на `body`. Они рисовались на корневом слое → при ЛЮБОЙ анимации/скролле браузер перерисовывал всё свечение заново.

**Сделано:**

- Добавлен `@media (prefers-reduced-motion: reduce)` — отключает анимации для тех, кто их не хочет (было полностью пропущено).
- Проверены все `@keyframes` — анимируют только `transform`/`opacity` (дёшево), багов нет.
- Убран `transition: all` (заставляет браузер следить за всеми свойствами) → конкретные свойства в `ChatPage.tsx`, `InboxPage.tsx`, `SetupWizard.tsx`.
- Точечный `will-change` на 7 бесконечно анимируемых элементах онбординга (`OnboardingModal.tsx`).

**Файлы:** `index.css`, `ChatPage.tsx`, `InboxPage.tsx`, `SetupWizard.tsx`, `OnboardingModal.tsx`.

## 2. Чат «не понимает контекст» — ГЛАВНОЕ ✅ (нужен живой замер)

**Ты был прав.** Чат искал по ключевым словам. Корень — в `backend/app/services/leads/icp.py` был **захардкожен один случай — «мраморная крошка»**: таблицы `_MARBLE_BUYERS`, `_MARBLE_POSITIVE` и т.д. Профиль клиента (ICP) обогащался ТОЛЬКО если в запросе было слово «мрамор». Для любого другого запроса ICP схлопывался до самого текста запроса → генератор поисковых запросов получал пустышку → мало/слабые лиды. Твой пример «найди производства где применяют мраморную крошку» «работал» только потому, что кто-то вручную прописал именно мрамор. Шаг в сторону — и поиск ломался.

**Что сделано:** добавлен общий **LLM-разбор промта** (`icp_parser.py`) — то, что ты и просил. Перед генерацией запросов LLM разбирает запрос для ЛЮБОЙ ниши и определяет:
- intent: ищем покупателей/потребителей продукта или компании в нише;
- buyer_segments — конкретные отрасли/типы компаний, которые ПРИМЕНЯЮТ продукт (ключевое);
- positive/negative keywords, excluded_industries.

Хардкод «мрамора» удалён. При сбое LLM — откат на старый детерминированный профиль (поиск не падает). Это новый Шаг 0 в pipeline (CLAUDE.md §5).

**Файлы:** новый `icp_parser.py`; вычищен `icp.py`; подключено в `pipeline.py`; тесты `test_icp_parser.py` (+ поправлены 2 теста, которые проверяли старый хардкод).
